# v0.48.0 — Web search for everyone

This week closes the search gap. Until now only Claude and OpenRouter
keys could search the web; every other provider — Chrome's built-in
model, Ollama, direct OpenAI — worked blind. Now any provider can search
over your own key, and any provider can read a specific page as clean
text. Around that, three external contributions polish the file viewer
and make tool activity audible to screen readers.

## Highlights

- **Web search with any provider.** Paste a [Tavily](https://tavily.com)
  key into the sidebar's new "Web search & reading" section and every
  provider gains a `web_search` tool. Keys follow the Slack rule: held
  in tab memory only, sent per call in the Authorization header, never
  echoed into tool results or errors. When provider-native search is
  active (Anthropic's server tool, OpenRouter's plugin) the fallback
  steps aside, and the system prompt always states exactly which web
  abilities a run has.
- **Read one page, cleanly.** A Jina Reader key adds `fetch_page`, which
  turns a single URL into clean text for any provider — useful when the
  answer is a page you already know, not a search. Both new origins were
  CORS-verified from a real browser page and added to the audited CSP
  allowlist.
- **Tool activity reaches screen readers.** The chat transcript now
  carries a polite live region that announces a tool chip's completion
  ("Posting to Slack — done / failed"), localized like the chips
  themselves, with no announcement spam on re-renders. Thanks
  @blut-agent (#35).
- **File viewer polish, from contributors.** Escape now closes the file
  viewer (thanks @xujunfeng1, #30), and a Copy button puts a viewed
  file's contents on the clipboard with reset-after-a-moment feedback
  (thanks @HaimiyaWasn, #31).

## Under the hood

- Packaged hatchlings reach the search pair through a new fail-closed
  `web` capability — an agent that doesn't declare it simply never sees
  the tools.
- A ProofLock audit policy (`.github/prooflock.yml`) now observes
  integrity-sensitive surfaces on every PR — CI workflows, test suites,
  dependency files, the security policy, verification tooling — and
  records what a change touches before any independent-review
  requirement tightens.
- The Slack e2e specs scope chip assertions to the transcript, since the
  new live region intentionally repeats chip text; the flake this
  prevents only reproduces under repeated runs, so live-region UI
  changes are now verified with `--repeat-each`.
- The Google verification docs record reality: branding verified,
  sensitive-scope data access submitted and in review.

## For contributors and forks

- Fresh good-first-issues: announce tool *start* to screen readers
  (#36), copy an assistant reply from the transcript (#37), and restore
  a workspace backup (#17) — claim with a comment before starting.
- Fork note: the Tavily and Jina origins ship in both `vite.config.ts`
  and the built-policy check, so forks that prune the CSP allowlist
  should keep the two lists in sync or drop both entries together.
